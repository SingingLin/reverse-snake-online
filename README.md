# 🍎🐍 反向貪食蛇：網路對戰版

這次你是那顆蘋果。這個資料夾是**可以網路對戰**的版本：一個 Node.js 伺服器，同時提供遊戲網頁和 WebSocket 連線。

單人的關卡模式、無盡模式、同一台電腦的雙人對戰都還在，主選單多了一個 **🌐 網路對戰**。

---

## 1. 在自己電腦上跑起來

需要 **Node.js 18 以上**。

```bash
npm install
npm start
```

看到 `反向貪食蛇伺服器已啟動：http://localhost:3000` 就成功了。

用瀏覽器打開 <http://localhost:3000>，再開第二個分頁（或另一個瀏覽器）也打開同一個網址，就能自己跟自己對戰測試。

> 想換 port：`PORT=8080 npm start`（Windows PowerShell：`$env:PORT=8080; npm start`）

## 2. 跟同一個 Wi-Fi 的朋友玩

1. 在跑伺服器的電腦查區網 IP
   - Mac：系統設定 → Wi-Fi → 已連線網路旁的「詳細資訊」
   - Windows：在命令提示字元輸入 `ipconfig`，找「IPv4 位址」
2. 朋友的電腦或手機打開 `http://你的IP:3000`（例如 `http://192.168.1.23:3000`）
3. 如果連不上，通常是電腦的防火牆擋住了，允許 Node.js 接受連線就好

## 3. 部署上網，讓任何人都能玩（以 Render 免費方案為例）

1. 把這個資料夾推到你的 GitHub（`node_modules` 不用推，已經寫在 `.gitignore`）
2. 到 [Render](https://render.com) → **New → Web Service** → 選這個 repo
3. 設定：
   - Runtime：**Node**
   - Build Command：`npm install`
   - Start Command：`npm start`
   - Instance Type：**Free**
4. 部署完成後會拿到一個 `https://xxxx.onrender.com` 網址，分享給朋友就能玩

注意：
- 伺服器會自動使用平台給的 `PORT`，網頁也會自動改用 `wss://`（加密連線），不用改程式。
- Render 免費方案在 **15 分鐘沒有任何流量**（HTTP 請求或 WebSocket 訊息）後會休眠，下次打開要等它重新啟動，第一次載入會比較慢。
- 房間只存在伺服器記憶體裡，伺服器重新啟動時，正在進行的房間會消失。

其他支援 Node.js 和 WebSocket 的平台（Railway、Fly.io、自己的 VPS、AWS EC2 等）也都可以，一樣是 `npm install` 再 `npm start`。

## 4. 怎麼玩網路對戰

1. 主選單 → **🌐 網路對戰** → **建立房間**，會拿到 4 碼房號（例如 `DYAN`）
2. 把房號告訴對手，對手在「網路對戰」輸入房號 → **加入**
3. 房主選自己要當 🍎 還是 🐍，按 **開始對戰**
4. 兩邊都用 **方向鍵或 WASD** 操作自己的角色；手機可以滑動畫面或按下方的方向鍵
5. 勝負：蛇咬到蘋果就是蛇贏；撐過 60 秒，或蛇撞到牆、磚塊、自己，就是蘋果贏
6. 打完房主可以按 **再來一局** 或 **交換角色**，戰績會累計

網路對戰時不能暫停，也不會跳出新手道具提示，免得卡住對手。

## 5. 架構說明

```
┌───────────┐   WebSocket   ┌────────────┐   WebSocket   ┌───────────┐
│ 房主的瀏覽器 │ ◀──────────▶ │  server.js  │ ◀──────────▶ │ 對手的瀏覽器 │
│ 跑遊戲邏輯   │               │ 房間＋轉送  │               │ 只負責顯示   │
└───────────┘               └────────────┘               └───────────┘
```

- **房主的瀏覽器負責遊戲邏輯**（host-authoritative）：蛇怎麼走、誰撿到道具、誰贏，都由房主那邊算，每 50 毫秒把完整狀態送給對手。
- **對手只送操作**：按下或放開哪個方向。
- **伺服器不懂遊戲**：它只管開房間、把訊息轉給同房間的另一個人，所以很輕量。
- 每次送的是「完整狀態」而不是「變化」，偶爾掉一個封包也沒關係，下一個狀態一到就補正。
- 對手的畫面在兩次狀態之間會自己先把動畫往前推，看起來比較順。

### 訊息格式

瀏覽器 → 伺服器：

| `t` | 內容 | 用途 |
|---|---|---|
| `create` | | 建立房間 |
| `join` | `room` | 加入房間 |
| `relay` | `d`（任意 JSON） | 轉給同房間的另一個人 |
| `leave` | | 離開房間 |

伺服器 → 瀏覽器：`created`、`joined`、`peer-joined`、`peer-left`、`room-closed`、`error`、`relay`

遊戲內容都包在 `relay` 的 `d` 裡：

| `d.k` | 方向 | 內容 |
|---|---|---|
| `lobby` | 房主 → 對手 | 房主選的角色、戰績 |
| `start` | 房主 → 對手 | 開始新的一局 |
| `snap` | 房主 → 對手 | 整個遊戲狀態（每 50ms） |
| `end` | 房主 → 對手 | 勝負、原因、戰績、最後狀態 |
| `in` | 對手 → 房主 | `d`：方向，`down`：按下或放開 |

### 伺服器的保護措施

- 每個房間最多 2 人，第 3 人會收到「房間已經滿了」
- 單一訊息最大 64 KB，每條連線每秒最多 120 則
- 每 15 秒 ping 一次，沒回應的連線會被關掉（例如手機直接關掉瀏覽器）
- 房主離開時房間關閉，對手會收到通知；對手離開時，房主可以等新的對手加入

### 已知限制

- 因為由房主負責判定，房主理論上可以改瀏覽器裡的程式作弊。要防作弊得把遊戲邏輯搬到伺服器上跑（server-authoritative）。
- 斷線不會自動重連，要重新加入房間。
- 只支援 1 對 1，還沒有觀戰。

## 6. 檔案結構

```
reverse-snake-online/
├── server.js          # HTTP + WebSocket 伺服器（房間、轉送、心跳）
├── package.json       # 只依賴 ws
├── public/
│   └── index.html     # 整個遊戲（2D/3D、關卡、無盡、雙人、網路對戰）
└── README.md
```

3D 用的 three.js 從 cdnjs 載入，所以玩家的瀏覽器需要能連到網路。
